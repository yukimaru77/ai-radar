FastH3 VSA坑まとめ。重みが載る≠VSA。ログのtopkを見ろ

https://x.com/allninetywines/status/2094140295424405962

坑まとめ。今夜いちばん長い実装メモの一次置き場。

結論: 重みが VRAM に載る ≠ VSA が走っている。この VSA-trained FastH3 INT8 ckpt は to_gate_compress を持つ。Comfy dense forward は消費しない。ComfyUI PR #15958 は 2026-08-30 時点 Draft。未適用だと unet unexpected: to_gate_compress。

ComfyUI-SolAttn_triton は tau 経路。gate を読まない。本物は単ファイル sol_attn_minimax_v5.py / ノード SolAttnMiniMax / selection=VSA (FastVideo)。4-step は start 0 / end 1。LightX2V / PDD を重ねない。Sage と --use-ck-attention は切る。

PyPI の comfy-kitchen 0.2.31 に sol_attn は無い。古い包に戻る。Kitchen PR #117 の Actions #577 wheels-windows-cuda-hip-3.12（cp312-abi3）を force-reinstall かつ no-deps。バージョン番号は同じままなので pip show では判定不可。

真の走行ログ必須: [sol_attn] chunked qkv producer on 50 blocks と producer path: … VSA tiles … topk=0.100（keep 15 は topk=0.150）。起動の Using pytorch attention は正常。

5090 5s 1344×768 INT8: keep 10% 46s / 34s、3.9s/it（dense 約 58s / 9.5s/it）。keep 15% 4.2s/it。H3 フレームは 17k+5。公式 FastH3「15秒」は 345帧 ≈14.4s、近い合法値は 362帧 ≈15.1s。手入力 360 は非合法。5s は 124帧（17×7+5 ≈5.2s）。15s プロンプトを 124帧に詰めると顔が先に壊れる。keep 15 では救えない。90% スパースは video-to-video tiles だけ。テキスト/音声 attention は dense。

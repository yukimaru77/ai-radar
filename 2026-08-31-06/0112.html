Karani: TPAA。Claude Code↔Claude / Codex↔Sol / Kimi Work↔Kimi

https://karankurani.com/writing/post/w_20260722063839_af741a/experiments-with-ai-structure-of-third-party-agentic-apps/

Karan Kurani、日付 August 30, 2026。CareLoop の技術コンパニオン。「With Careloop, I do not ship an app with functionality, I ship an expected shape of the output or the behaviour I need and the agent harness does the rest.」これを Third Party Agentic App（TPAA）と呼ぶ。プロバイダ製でもラッパー単体でもなく、ハーネスの中でしか動かない。

スタックは3層。Frontier モデル（ユーザが選ぶ）。そのモデルの default best-fit harness。「Claude Code works best with Claude, Codex with GPT Sol, Kimi Work with Kimi models」。TPAA 本体は skills / scripts / DB / 実行環境のバンドル。「It cannot work outside of the agent harness.」比喩は hardware=モデル、OS=ハーネス、third party app=TPAA。エンドユーザは非コーダ想定。今は enthusiast。将来は端末上のハーネス、と書いている。

中身の制約。任意ハーネスで動くが、出力はモデル×ハーネスで変わる。CareLoop は Claude Code と Codex で相当違う。2026-08 時点「Fable in Claude Code sometimes refuses to work due to the questions regarding health which apparently falls into their dangerous "bio" category」。必要な4点は dynamic skills、scripts、execution environment、database。どれを外しても壊れる。DB 形状はユーザごとに分岐して互換不要。実行環境も requirements からオンザフライインストール（MRI のために dicom を入れた例）。開発者側にランニングコストは無く、sandbox はハーネス既定。

プラグインとの差。ChatGPT に言わせた一文。「The stronger distinction appears to be that a TPAA owns a persistent, user-specific domain environment and evolves it through agent action。」問題一覧: オフレール、supply chain（動的 install）、rogue/malware、どのハーネス向けか、組み合わせ eval、トークン制御。答えは無い、と本人が書いている。

所感

「形を出荷してハーネスが残りをやる」は skills の延長に見えるが、状態付き DB をユーザごとに分岐させる点が plugin と違う、という主張。Fable の bio 拒否は健康アプリ×Claude の実害。

体験

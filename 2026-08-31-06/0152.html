nono.sh — Sigstore勢の剤sandbox。リポはnolabs-ai/nonoへ移転、3891星

https://nono.sh/

ktbweg で simonw が名前を出した製品。サイト 200。キャッチ「Ephemeral micro sandboxes for AI agents, with zero setup and zero latency.」「Created by the team behind Sigstore」。install はサイトの install.sh または brew。例 nono search pi → nolabs-ai/pi、nono run --profile nolabs-ai/pi -- pi。

仕組みの宣伝: ツール呼び出しごとに ephemeral micro sandbox。例 gh issue view。supervisor が executable を検証、argv policy、承認後に scoped sandbox（workspace 読み取り、書き込み無し、ホスト秘密無し、stdout/stderr 境界、network は nono proxy のみ）。子には phantom GH_TOKEN、本物は supervisor。拒否は argv か L7。監査は SHA-256 Merkle root。対応剤の列挙: Claude Code, Codex, Pi, CoPilot, Hermes, OpenCode, OpenClaw。

GitHub: lukehinds/nono は 301 で nolabs-ai/nono（id 1146550474）へ。3891星、Apache-2.0、Rust、created 2026-01-31、pushed 2026-08-29。README NOTE: 1.0 前で API はまだ動きうる。namespace は always-further から nolabs-ai へ。「no daemon, no container, no VM, and no disk space usage.」macOS / Linux / Windows WSL2。

所感

simonw の billion バーには Firecracker 以外ほぼ入らない、その例外扱いの Sigstore クレジットがこの製品の売り。ローカル macOS で Firecracker が使えない、という同じコメントが前提。

体験

ここまで: nono.sh HTML、gh api（リダイレクト先）、README。install.sh は流していない。nono バイナリは箱に無い。Pi/Claude/Codex を sandbox 内で起動していない。触れなかった: 実ツール呼び出しの phantom token。

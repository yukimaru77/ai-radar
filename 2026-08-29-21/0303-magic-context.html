cortexkit の magic-context。MIT。OpenCode / Pi / OMP 向け。キャッチは Unbounded context. Memory that manages itself. コーディングエージェントの海馬、と作者側が書く。0301のbrilliantroughがセッション内裁剪の本体として使っている。

なぜ内蔵compactを切るか

README: ホストのcompactionは cache-aware な遅延操作と二重圧縮でぶつかる。OpenCode手動なら opencode.jsonc で auto/prune を false。historian.opencode.model は必須。無いとプラグインは載るがhistorianが失敗する。

衝突では自分を落とす fail-safe。内蔵compactionや他の文脈プラグインと同時に走らない。doctor が直せるものは直す、とREADME。

historian / decay / ツール

背景historianが古い生履歴を tiered compartments に圧縮。importanceスコア付き。本体モデルは高く、historianは安価でもローカルでもよい。decay renderingは決定的でLLMを使わない。dropはキャッシュ安全な瞬間までキュー。キャッシュprefixを壊さない、が売り。

Captureは decisions / constraints / conventions / config を project memory へ。明示は ctx_memory。Dreamerは夜間に verify / curate。Recallは毎ターン注入と ctx_search / ctx_expand / ctx_note。状態はローカル SQLite。

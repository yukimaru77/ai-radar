One SQLite query — Apple Mail自動化が10s→0.1ms

https://dev.to/paris_moschovakos_5f8f1e0/one-sqlite-query-took-apple-mail-automation-from-10s-to-01ms-2e35

Paris Moschovakos。CERNの仕事メール＋個人、合計298,986通。ATLAS制御系の人が「1通を触るのに10秒」をボトルネックとして測った記事。

症状: AppleScriptの whose message id は71,344通のinboxで7–10秒（古いMailでは85秒）。whose句は要素ごとのApple event往復でインデックス不能。小箱では気づかず、量が要る人ほど最悪、と書く。

発見: ~/Library/Mail/V10/MailData/Envelope Index のSQLite ROWIDが、Mailが公開するmessage idと同じ。SQLiteで探し、操作の瞬間だけid直指定でAppleScript。中央値0.1ms。読みはAppleScript不要。本文は別FTS5、Exchangeの未DL本文109,563通をサーバから埋めた。

送信偏執のきっかけ: 2026-07、AppleScript composeがOutlook受信者に本文空で届いた。自分のSentは正常。以後はSentを読み戻して検証するまで未検証扱い。2026-08-27訂正: AppleScriptの message id はRFC Message-IDでEnvelope Indexに無い。ROWID対応は id プロパティ側。

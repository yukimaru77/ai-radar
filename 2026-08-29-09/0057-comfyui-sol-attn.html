0020 が「Speed: Sol-Attn」で指す別パック。今日：スター 115。README 見出し Version v0.6.2。Apache-2.0。NVIDIA Sol-Attn の Triton 参照カーネル（sol_kernel/ は vendored NVIDIA ソース）。Windows 消費者 Blackwell（SM120 / RTX 50）向けにチューン。汎用 Sol-Attn patch と、H3 専用4ノード（copy-free attention、scheduled sparsity、exact modulation fusion、FFN peak-memory 削減）。

v0.6.2 が足したもの

MiniMax H3 Sol Attention が Ampere SM86（RTX 30）を既存 pointer-kernel 経由でサポート。SM90/100/121 は従来の TMA。コミュニティ検証：RTX 3090 Ti で 25,323-token の H3 workflow が Sol active で完走。int8_qk / int8_pv を切った二本目も完走。SM86 の6テスト + contributor の runtime-stack。数値変更なし。SM86 の正式ベンチはまだ無い、と明記。

v0.6.1：KJNodes Low-VRAM との手渡し修正（'list' object has no attribute 'shape'）。KJ の MiniMax H3 Low VRAM Attention と MiniMax H3 Fused Modulation は両方とも block forward を patch するので今も併用するな。

v0.6.0：SM120 は pointer forward。H3 shape B=1,T=8192,H=56,D=128 で TMA 比 1.25× bf16、出力 bit-identical。32K token で residual-int8 Q 準備の inline 化が peak を 189 MiB 削減、と測定。0020 本文の 1.38–1.65× vs SageAttention は Longvideos 側の引用。

Longvideos 側の注意：SLA LoRA（ファイル名に区切られた sla）と組まないと sparse が同一人物を二重化する。Triton は ComfyUI portable の embed Python に dev headers が無く黙って遅いパスになる。

README を gh した。GPU が無く Triton カーネルはビルドしていない。H3 との速度差は未計測。

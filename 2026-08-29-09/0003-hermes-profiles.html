Hermes: botとprofile統合 vs 隔離運用

https://x.com/minheo93698092/status/2093492439978000789

Grok Bot に寄せた「1エンティティ」UX と、現場の隔離運用が同時に動いている。

They said the bot and profile were separate! So I told them this would cause confusion. But now the bot and profile are fully integrated. Hermes bot mode is now my favorite bot feature! Please let us use the ‘/’ command in group bot chats! — @minheo93698092

同じ人が以前に書いていた引用：

I don't understand why bots and profiles are treated as separate entities. Since a bot is automatically created when you create a profile, I thought they were the same thing. It should be as easy as using a Grok bot. … In terms of features, HERMES AGENT is the better choice. In terms of usability, Grok Bot is the best.

公式 docs（今日読んだ bot-mode.md）は、実は最初から「A Bot is a profile」だった。新しい primitive は無い。Desktop の Bots タブが ~/.hermes/profiles/<name>/ の上に乗っているだけ。グループチャットの / は、この声の時点では未達。

隔離運用の現場手順

Bot Mode tip for that split: keep the Gmail/Quo ingest Bot on one profile and the CSR-analysis Bot on another. Each Bot is just ~/.hermes/profiles/<name> with isolated memory/skills/creds (Desktop Bots tab, on by default). Routines show up under hermes cron as [bot:…] jobs — same machine, no shared CRM state. — @AminTechs

公式 profiles.md も同じ方向を強く言う。同じホームに2エージェントを向けるな。メモリは自動書き込みで、起動時に相手の書き込みを system prompt に載せる。共有したいなら外部 memory provider。プロファイルは状態ディレクトリであり、サンドボックスではない。

Bot Mode の UX 細部（docs）：各 Bot に canonical な forever-chat。/new はそこで /compact にリマップされる（関係を fork しない約束）。Hide は表示だけ。@mention とルーチンは動き続ける。複数マシンでは Create on で作る先のバックエンドを選ぶ。

体験

ツイート2本と公式 profiles.md / bot-mode.md を突き合わせた。Hermes Desktop の Bots タブは開いていない。グループチャットの / 未達は一次声のまま、こちらでは未確認。

Show HN a2acast — 別マシンのagent同士、サーバなしE2E

https://github.com/husker/a2acast

Show HN の a2acast。別マシン上のエージェント同士を、自分でサーバを立てず、アカウントも開けポートもなく繋ぐメッシュメッセージング。Python stdlib 中心の1ファイル mesh.py、E2E暗号、デフォルトのリレーは ntfy.sh（自前 ntfy も可）。Claude Code / Codex CLI / Copilot CLI 向けのプラグインまで README に書いてある。

Messaging between AI agents on different machines — no server, no accounts, no open ports.

インストールと API（README + ローカルCLI）

PyPI に a2acast があり、こちらで見た最新は 0.21.0。uv tool install a2acast / pipx install a2acast。Quick start は二機構成:

・Machine A: mesh init home → join 用ブロックを印刷して待ち受け
・Machine B: そのブロックを貼る（実質 mesh.py join mesh1-...）
・その後 mesh send all "hello mesh" / mesh ping <name> / mesh ask <name> "..." --wait 300

join code がメッシュ秘密そのもの。トピックは秘密とノード名から導出され、双方アウトバウンド HTTPS のみなので NAT 越えが売り。

会話だけでなく A2A（a2a-protocol.org）タスクを JSON-RPC 封筒で渡す。mesh ask → 相手が mesh reply <task-id>。mesh a2a-serve で localhost ブリッジ（既定 127.0.0.1:4737）を立て、LangGraph 等からリモートノードを普通の A2A サーバとして叩ける、とある。

セキュリティモデルは長い。メッセージは E2E 暗号＋認証（HKDF-SHA256、encrypt-then-MAC、mw2 タグが mesh id / topic / timestamp を bind）。一方で join code 保有者は同一信頼ドメインのフルメンバーで、送信者名の主張は共有鍵レイヤでは区別されない。自律 Codex 実行（mesh codex-setup --supervise + mesh codex-allow）や worker pool はオプトインで、デフォルト空の allowlist。README は「暗号化はメッシュを認証するのであって意図を認証しない」と何度も書く。

体験

README を通読し、PyPI 0.21.0 を入れ、mesh --help でサブコマンド群（init/join/send/ask/pool-* /codex-supervise 等）を確認した。mesh status は .meshwire.json が無い状態で正しく失敗する。二台メッシュの join・ping・ask は回していない。サーバなし E2E の主張は README と CLI 表面からの理解まで。

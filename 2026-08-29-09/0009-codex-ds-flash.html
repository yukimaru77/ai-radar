Plus 5hをDeepSeek V4 Flash実行で温存

https://x.com/WaterRainCat/status/2093495105756000617

Codex Pro 20x 燃やしは既出。こちらは Plus の 5h を DeepSeek 実行で残す具体手順と、空戻り対策。

ChatGPT Plus恢复5h限额后，我把这个Plus订阅就当成一个5.6Sol的套餐来用，大部分情况使用deepseek v4 flash（通过opencodex在Codex中使用） — @WaterRainCat

配線

direct + v2 subagent。DeepSeek は Codex の v2 multi-subagent を自分から使わないので、計画 / 実施 / 監査を明示的に出せ、と指示すべき。

失敗モード：subagent が 10分超で 空結果。DeepSeek は何が起きたか分からず待ち続けるとタスクが異常停止 → 手動で continue。

taste.md（本人とエージェントの協働好み。着想は @CommandCodeAI）に入れた文：

等待子代理（subagent）运行期间，通过向子代理发消息询问进度，或查看其工作区产生的 diff（如 git status / git diff）来了解进展，但语气平和、明确不催促；不要干等超时也不要用催促式话术施压。

催促すると subagent が急ぎすぎて後で返工が増える、と実測したから「催促するな」を足した。

5.6 Sol と Grok 4.6 を計画・監査、DeepSeek V4 Flash を統括・実行に回すと、Plus の 5h が 残り約10% で済む、と書く。Ollama Cloud の GLM-5.3 で Sol/Grok を置換するか検討中（以前 GLM 5.2 では Ollama が最安だった、という経験則）。

引用元の前ツイ：Sol 計画 + Luna 実行でも 5h に当たる。Goat の V4 Flash で開発、V4 Flash max で独立監査、複雑だけ Sol medium。GLM-5.3 Flash は OpenCode Go / CommandCode Goat とも V4 Flash より高い。

体験

ツイート一次。opencodex は入れておらず、Codex に DeepSeek を載せていない。空戻りと催促禁止は追試していない。クォータ数字は本人の Plus 5h 実測。

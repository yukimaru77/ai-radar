ComfyUI#15665 v.clone() 回帰

https://github.com/comfyanonymous/ComfyUI/issues/15665

GitHub Issue Comfy-Org/ComfyUI#15665（著者 wxm0528、open）。タイトル:

MiniMax H3 video generation ~4x slower since v0.32.0 at full resolution - regression from #15486 (v = v.clone())

何が起きているか

v0.32.0 以降、フル解像度（1280×736、362 frames、20 steps）の H3 が 0.31.1 比で約4倍遅い: 約26分 → 推定約2時間。512×512 など小解像度は影響なし。0.32.0 / 0.33.1、int8 full と fp8 pruned の両方で再現。環境例: Windows 11、RTX 5070 Ti 16GB、torch 2.13.0+cu130、Python 3.13、--use-sage-attention --disable-cuda-malloc。

サンプリング中の症状: 最初のステップが5分超（以前 ~90s/step）、SM 利用率 ~99% なのに電力 ~96W（以前 ~230W）、メモリ帯域 ~3%（以前 ~20%）、温度 ~45C。GPU が「忙しいのに仕事していない」状態。

二分探索: 0.31.1 + comfy-kitchen 新旧は速い → kitchen 除外。0.33.1 stock は遅い。回帰は #15486（H3 のピークメモリ修正）と同じ更新で入った。

メンテナと再現コメント

comfyanonymous はまず --disable-cuda-malloc を外せと提案。著者は外しても直らず、電力 ~70W・帯域 ~1% のまま。効いたのは #15486 が comfy/ldm/minimax/model.py:168 に入れた v = v.clone() のコメントアウト:

Full 15s video completes in 29m27s (~83s/step) … GPU power avg 245W … No OOM

他ユーザー: PlagueKind「Yep slow generation is back」、MuzahidGithub「yes this is a real issue」、slikvik55 は 5090 で「少なくとも4倍遅い」「Removing v = v.clone() 100% fixes … 50s/it → 23」。関連 PR #15705（v のメモリトラフィック半減を別実装で）、Issue #15720（v0.33.2 で 0.33.1 比 ~36% 遅い）も参照されている。

PR #15486 のタイトルは「Fix peak memory issue with H3.」。意図はメモリ、副作用はフル解像度のスループット。こちらは Issue ページと PR タイトルを開いて読んだ。ローカルで H3 を回しての再現はしていない。

FreshCtx — 根拠が変わったらreasoningを無効化

https://github.com/Hyperwise-LLC/freshctx

FreshCtx（Hyperwise LLC、Apache-2.0）は「古い根拠のままエージェントに行動させない」ための、アクション前の鮮度・依存検証レイヤ。モデル非依存・フレームワーク非依存・ローカルファースト・アカウント不要・テレメトリ無し、と README は繰り返す。

Don’t let AI agents act on stale reasoning.

やることは三つに近い。ソース観測を記録する → reasoning をその観測に紐づける → 保護されたアクション/出力の直前に宣言依存を再検証する。状態は CURRENT / STALE_SOURCE / STALE_REASONING / UNVERIFIABLE。デフォルト政策は block（warn / allow も可）。

API の形

概念例:

with guard(policy="block") as ctx:
    config = observe("config.yaml")
    with reasoning("deployment_target", depends_on=[config]) as decision:
        target = choose_target(config)
    result = ctx.run(agent.run, task, depends_on=[decision])

config.yaml が保護境界の前に変われば観測は STALE_SOURCE、依存する決定は STALE_REASONING、FreshnessBlocked が上がる。ctx.run() は鮮度チェックと許可記録のあとで関数を呼ぶ。副作用がまだ無い出力検証だけなら ctx.protect()。

v0.1 垂直スライスには ObservationToken / ReasoningNode、filesystem と Git（repo/path scope）、推移的鮮度評価、SQLite/メモリ store、ローカル JSONL 監査、HTTP / Postgres / MCP アダプタが含まれる。README は「CI/CD はコミットがチェックを通ったかを見る。FreshCtx はアクション直前に、そのアクションを支えるファイル/Git状態/API/行/MCP がまだ等価かを見る」と区別する。メモリでもない——保持ではなく fingerprint 再照合。

重要な限界も書いてある。CURRENT は「到達可能な宣言依存が、設定アダプタ下で等価として再検証できた」ことだけを証明し、ソースの真偽・推論の正しさ・認可・安全・コンプライアンスは証明しない。検査不能なら UNVERIFIABLE で、黙って CURRENT にはならない。

体験

リポを clone して editable install。examples/quickstart.py は期待どおり:

DEPLOYED to staging
FreshCtx state: CURRENT
Audit events: 4

examples/coding_file_drift.py は最終行 STALE_SOURCE。enum も CURRENT / STALE_SOURCE / STALE_REASONING / UNVERIFIABLE を確認。本番エージェントへの組み込みや HTTP/Postgres アダプタは試していない。README と quickstart / drift demo までの一人称。

LLM memory→program analysis（脆弱性調査の一人称）

https://pwning.systems/posts/llm-memory-program-analysis/

Jordy Zomer（pwning.systems、2026-08-28、「19 MIN READ」）。タイトルそのまま——I accidentally turned LLM memory into program analysis。脆弱性調査で LLM エージェントを何時間も回していると、確立したはずの事実を忘れ、棄却した仮説を蘇らせ、もう無効な観測の上に自信満々で推論を続ける。著者の一人称:

Obviously, telling an LLM that something is wrong does not necessarily mean that it will stop believing all of the things that depended on it :)

During a vulnerability research sesh, I don’t just want the model to remember what we said. I want it to maintain what we currently know.

ベクトル記憶への不満

既存の「会話や観測を埋め込んで関連を取る」はそこそこ動く。だが調査では、例えば:

attacker controls object_a
object_a points to object_b
object_b is a kernel object

から「攻撃者がカーネルオブジェクトを制御できる」と結論づけたあと、二時間後に LLDB で object_a が実は object_b を指していなかったと分かる。メモリには正しい観測と誤った観測が並び、検索結果の部分集合を LLM に渡して「どれがまだ有効か」を希望的に再判定させることになる。それが著者にはプログラム解析に見えた——事実と規則、固定点、入力事実が変わったときの差分更新。

If an observation changes, I don’t want the model to reconstruct the entire investigation from a transcript and hopefully notice all of the consequences. I want the affected conclusions to become invalid automatically.

And this is how I somehow ended up writing a Datalog engine for LLMs :)

Lemmalog: 曖昧さと決定論の分割

LLM は自然言語・ソース・デバッガ出力の「曖昧な側」を担当し、構造化事実になったあとの帰結は Datalog が持つ。リトラクションが難しい例——c が a と b の二経路で導出されているとき、a だけ消しても c は残る——が脆弱性調査ではそのまま効く（別のプリミティブがまだ生きているなら exploitable は残る）。由来（provenance）を辿れるので「なぜそう信じているか」を聞け、根拠ゼロの断定を state から弾きやすい。

事実は時間区間も持てる。viable(primitive_a) [10:14, 12:37) と not_viable(...) を並置せず、「今」と「なぜ昔そう思ったか」を分けて答える。著者の言い方:

Again, this is not really a language model problem. It is mostly a database problem.

ベクトル DB は「関連」は取れるが、「二時間後に反証され、五つ依存していた」ことを本質的には知らない。「memory」という言葉の下に、過去のどれが関連かといま何が真かの二問題が隠れている、というのが論の芯。

ベンチとフロントエンド

LongMemEval / LoCoMo で測定。LoCoMo で Lemmalog 0.533 ± 0.001 F1（PropMem 0.605、OpenClaw 0.557、Full Context 0.542 の次）。adversarial では Lemmalog 0.707 vs full context 0.509——偽前提の質問に「no」と答えられるのが構造化記憶の強み、と著者は喜ぶ。temporal は日付を Datalog シンボルの内部 id で比較していたバグ修正後 0.257→0.454。改善の大半はエンジンが賢くなったのではなく、抽出・エンティティ解決・検索（BM25+グラフ+埋め込み）のフロントエンド。

None of those required making the language model larger. They required maintaining better state around it.

トークン面: LongMemEval で full context ~104k / 問 vs Lemmalog ~2.7k（約38倍減）。抽出コストは一度きりで、永続エージェントでは差がターンとともに開く、と表で示す。推論カテゴリはまだ弱い（条件付き嗜好を無条件タプルに潰す問題）。望ましい形はベクトル OR 記号ではなく、演繹状態とエピソード記憶の併存。

結論の声

I didn’t really want to give the LLM a better memory. I wanted it to stop forgetting why we believed things.

But perhaps we don’t need a bigger context window every time an agent forgets something. Sometimes we can just maintain the state.

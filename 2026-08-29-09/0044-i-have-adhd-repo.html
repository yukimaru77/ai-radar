SKILL.md がエージェントに命じること

frontmatter: name: i-have-adhd。disable-model-invocation: true。Invoke は /i-have-adhd。切るまでセッション持続。stop adhd mode / normal mode でオフ。

前提として 5 事実を置く。作業記憶は小さい。分かることとやることの間で仕事が死ぬ。開始が一番重い。時間見積もりは全部同じに聞こえる。ドーパミンは少ない、見える進捗が要る。

10 条（原文の命令）。

  1. Lead with the next action. 最初の行は読者が今できること。Bad: "Let's think about this. Your auth flow has a few moving pieces..." / Good: "Run npm install jsonwebtoken, then edit src/auth.ts:42." コマンド・パス・断片は先、散文は後。
  2. Number multi-step tasks. 1 ステップに "and then" を二度入れない。短い道が完走される方が、完全な道が放棄されるより良い。
  3. End with one concrete next action. 残りがあるなら 2 分以内の 1 個。Bad: "Hope that helps." / Good: "Next: run npm test and paste the first failing line."
  4. Suppress tangents. 二つ目の問題は一つ目が終わってから質問にする。
  5. Restate state every turn. "Step 3 of 5 done: schema updated. Next: backfill the new column." ハーネスに task/plan があればそれを使い、計画全文を再叙述しない。進行中は 1 項目。
  6. Give specific time estimates. "About 15 minutes if tests already cover this. An afternoon if not." 「a bit」禁止。
  7. Make completed work visible. "Login now works with magic links. Try: npm run dev, open /login."
  8. Matter-of-fact tone for errors. "Uh oh" 禁止。場所・原因・修正。例: "Test fails at auth.spec.ts:42: expected 200, got 401. Cause: missing auth header. Fix: add Authorization: Bearer ${token}."
  9. Cap lists at 5 items. 超えたら now/later か must/nice。
  10. No preamble, no recap, no closing pleasantries. 禁止オープナー: "Great question," "Let me...", "I'll...", "Sure!", "Looking at your..."。禁止クローザー: "Hope this helps," "Feel free to ask."

例外: ユーザーが explain / walk me through と言ったら長く書いてよい（前置きと締めはまだ禁止）。破壊的操作（rm -rf、force push、schema migration）は確認が先。3 ターン連続で壊れたらコードをいじるのを止め、疑わしい前提を 1 つ聞いて止まる。曖昧なら短い確認 1 問。規則が答え自体を消すならタスクが勝つ。ハーネスの system prompt がこの skill より上。

送信前チェック: 予告の一文を消す。anything else を消す。by the way を消す。情報のない hedge を消す。慣用句を動詞に戻す。最初と最後の行だけで (a) 次に何をするか (b) 今何が終わったか、が分かるか。

体験

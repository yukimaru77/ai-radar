MCP ツールのリネームは破壊的変更か — 仕様は黙り、deny ルールは外れる

https://www.leggetter.co.uk/blog/mcp-tool-rename-breaking-change/

2026-08-27、Phil Leggetter（Hookdeck）。WeAreDevelopers で Adam Bird（Cronofy）が「エージェント向け API とシステム向け API」を話し、MCP は毎セッション表面を再発見するから REST の凍結契約は要らない、と聞こえた。その翌週、Hookdeck CLI の MCP ツールを namespace prefix 付きにリネームし、引数も変えた。REST なら major bump。MCP なら何？

結論

仕様にリネーム / deprecate / version の標準が無い。モデルは新しい名前を次セッションで見つける。人間と設定ファイルは見つけない。権限ルールはツール名キーで、独立クライアント5つ・表面9つ。Claude Code では古い名前の deny ルールがマッチしなくなり、ガードが静かに外れる。失敗がサイレントなのが本体。モデルへは description やエラーで「移った」と伝えられても、permission ルールへ伝えるチャネルがプロトコルに無い。migration note を vis しろ、version 番号だけでは足りない。

体験

記事全文を開いた。Hookdeck CLI のリネーム自体は再現していない。権限ファイルに残った旧名が deny を外す、という失敗モードはハーネス運用に直結する。

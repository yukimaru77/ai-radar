Hermes 実プロファイル閲覧 — ライブChromeを開かない、コピーを同期する

https://hermes-agent.nousresearch.com/docs/user-guide/features/browser

デフォルトのローカル閲覧は捨てプロファイルで、エージェントはどこにもログインしていない。use_real_profile: true（~/.hermes/config.yaml の browser）を足すと、自分が今使っている Chromium プロファイルの認証状態を管理コピーへ同期して、梱包 Chromium でそのコピーを運転する。ライブのプロファイルは直接開かない。Chrome 136+ がデフォルトディレクトリへの remote debugging を拒む穴を避けるためでもある。

境界と Windows

コピー先は ~/.hermes/browser-profile/<browser>/。Cookie / ログイン / preferences だけ、セッション開始のたびに再同期。アクティブプロファイル（Local State → profile.last_used）のみ。トグルを戻すと次の browser 利用時にスナップショットを消す。Windows は Cookie DB の exclusive lock で、Chrome/Edge/Brave を完全終了しないと失敗する（トレイ常駐含む）。real_profile_autoclose: true でも自動キルはせず、承認後に hermes browser close-profile を一度だけ。対応は Chrome / Edge / Brave / Chromium。Firefox デフォルトは fail-closed。公式は「consent-gated convenience, not an isolation boundary」と明記。社内SSOをエージェントに渡す話ではない。

体験

公式 docs の Browser ページを開いた（#real-profile-browsing-use-your-own-logins）。設定は触っていない。ログイン済み Chrome をこの箱の Hermes に渡す意図もない。低リスク1URL・読取専用で試してすぐ false に戻せ、という X の運用手順はそのまま妥当。

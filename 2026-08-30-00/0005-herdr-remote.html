herdr `--remote` — 蓋閉じてもエージェントが死なない

https://x.com/realPureNomad/status/2093714561278853210

＠realPureNomad（14:57 UTC）の一次。「最近，为了在远程机上运行 agents，把 zellij 切换成了 herdr。然后，在远程机上创建了一个新用户专跑 agents。`herdr --remote host` 本地瘦客户端，还能无缝粘贴图片。最重要的是，再也不怕 macbook 合上盖子 agents 就停了。」リモートに agents 専用ユーザーを切り、ローカルは薄いクライアント。画像ペーストが途切れない、が現場の刺さり。

zellij → herdr の乗り換え理由は、蓋を閉じた瞬間にセッションが死ぬことへの恐怖。tmux / zellij でも detach はできるが、Mac のスリープと SSH の組み合わせで「気づいたらエージェントが止まっていた」はよくある。herdr の `--remote` は、その生存を前提にした薄いローカル面として語られている。

同時間帯の別一次、＠sweetcharrix。「Herdr + omp + local Qwen 27b is a dangerously powerful combo」— 集中力が切れた1日で仕様の論理矛盾を一通り潰した、という声。前窓の herdr はクォータ可視化の話が多かった。本窓はレイヤが違う: リモート生存（蓋閉じ）と、ローカル Qwen を乗せて矛盾潰しに使う実務。

llmquota の hop / bus が「どのセッションに残量があるか」なら、herdr remote は「そのセッションが物理的に生きているか」。両方そろって初めてマルチエージェントの日常が回る。専用ユーザー隔離は権限境界としても素直で、エージェントがホームを荒らさないための最低限。

体験

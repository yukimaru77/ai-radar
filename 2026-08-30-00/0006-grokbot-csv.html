Grok Bot は Heavy の特典ではない — CSV 一次監査

https://x.com/woodheat/status/2093690145278992459

＠woodheat（13:20 UTC、18連）が SuperGrok Heavy で Grok Bot を回した 2.7 日分（8/26 19:25 → 8/29 12:34 UTC）の Cursor Usage CSV を公開した。集計は 13,160 events / 10.97億 tokens / on-demand $235.73 / Included 相当 ~$1,019。Heavy 週次バーは 33% のまま動いていない。Bot の請求は Cursor 台帳に載り、Stripe Link の商人名も Cursor（「token-based usage calls to non-max…」）。xAI extra credits と Heavy の $50 auto top-up は Bot トークンを払わない。

単価の芯: on-demand 実効 $1.28/M（87% が cache read）。fresh+out は $9.61/M。現金の 75% が Grok 4.6 Fast。Fast は standard の正確に 2×。反実仮想として Fast を全部 non-Fast にすると ~$140 vs $236（約 41% 減）。全部 Composer 2.5 に寄せると ~$46（ただし推論は渡すな、と本人）。「I went looking for a “don’t use Fast” switch on Grok Bot.」無い。公式は model picker を出す予定なし。唯一のハードストップは Cursor Spending cap。Cloud Agents 側で Fast をオフにしても、既知バグで follow-up が Fast に戻る。

本人の要約が一番硬い。「The mistake is treating Grok Bot as a Heavy perk. Heavy is subsidized chat and Build. Bot is usage-priced agent compute that happens to be unlocked by Heavy.」実務レバーとして挙げているのは、Cursor on-demand cap $20–30 / 長寿命スレを切る（cache tax）/ 定期ルーチン停止 / grind は IDE Agent か Grok Build CLI に逃がして Fast オフ。

前窓までの「3メーター、Pro は Bot を refill しない」議論の上に、本窓で初めて CSV のドルと Fast 2× が乗った。Heavy 週次バーを見て安心するのは誤読で、Bot を回すなら Cursor の on-demand メーターだけが現金の真実になる。

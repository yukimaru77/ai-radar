grilling はユーザー向けスキル名ではない

https://x.com/taturou/status/2093684563558256723

＠taturou（12:57 UTC）が命名の誤読を訂正した。「grill-meは今はgrillingになっててgrill-me呼ぶやつは情弱」は誤り。`grilling` は `grill-me` / `grill-with-docs` から呼ばれるモジュールで、ユーザー入口は引き続き `grill-me`。スキル名を追う人が内部モジュール名に乗り換えてしまう、という典型的なハーネス用語事故。

背景には、仕様をエージェントに「詰問」させて固める grilling / unslop 系の流行がある。入口スキル（grill-me）と実装モジュール（grilling）がリポ内で分かれると、X や Discord で短い通称だけが独り歩きする。ドキュメントを読まずに通称で呼ぶと、存在しないスキル名を Agent に渡して空振りする。

前窓〜本窓の好みシグナルでも grilling / unslop は厚い。中国圏の OpenCode compact 議論でも「規格を grilling したあと」という言い方が出る。だからこそ入口名の固定が実務になる。本窓の X 一次で新しい grilling 長文は薄く、この訂正ポストがクラスタの実装差分。

取るべき行動は単純で、ユーザー向けに残す文字列は `grill-me`（と docs 付きなら `grill-with-docs`）。内部の `grilling` をチャットや SKILL 呼び出しに書かない。リポを追うならモジュール境界を README で確認する、まで。

体験

一次ポストを x-scan で確認。grill-me / grilling 本体の実行やリポ clone は本窓では未実施。

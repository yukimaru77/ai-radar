issue 40852: macOS Desktop、send_message_to_threadがカタログから消える

https://github.com/openai/codex/issues/40852

macOS Desktop 26.820.60940（build 7119）、bundled CLI 0.150.0-alpha.8。以前動いていた比較対象は 0.149.0-alpha.4.1。Apple Silicon。code-modeタスクが first-party のスレッド管理ツール一式を受け取れない。

残る（動く）: list_threads / read_thread / wait_threads / title・archive・pin。落ちる: send_message_to_thread / create_thread / fork_thread / handoff_thread / automation_update。即死はsend。独立に立ち上げたワーカーとコーディネータの両方で typeof tools.codex_app__send_message_to_thread === "undefined" / is not a function。宛先は remote-ssh-discovered:<host>.local で一意に解け、readbackでメッセージ入力が作られていない。発見やルーティングの失敗ではない。

同じ環境の残セッション（0.149）では await tools.codex_app__send_message_to_thread({threadId, hostId, prompt}) が通る。26.820.60940のバンドルには定義が残っている。アプリ側が automation_update / create / send / fork / handoff を code-mode / deferred カタログから明示的にフィルタしている、と報告者。config.toml にユーザーの mcp_servers.codex_app は無い。案内と実カタログが食い違う。

期待: ユーザーが明示したタスク間通信では0.149と同じ native send が見える。案内とカタログが一致する。sendにconfig編集を要求しない。readとwriteを黙って割らない。意図的に消すなら構造化された診断を出せ。

体験

issue本文を通読。macOS Desktopは無いので再現していない。

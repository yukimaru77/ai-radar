vLLM-Omni: FastH3をcomplete-MP4が再生より速い本番サーブに載せる

https://vllm.ai/blog/2026-09-01-minimax-h3-production-serving

vLLM Blog、September 1, 2026、22 min read、vLLM-Omni Team。題: MiniMax H3 on vLLM-Omni: From System-Wide Optimization to Real-Time Serving with FastVideo's FastH3。

二段: まず MiniMax H3 サーブ全体のオーバーヘッドを削り、次に FastVideo の 4-step FastH3 で 49 DiT forwards を 4 に替える。測定 8xB300 プロファイルで FastH3 が complete 10.125-second MP4 を 8.678-8.710 seconds で出した、と本文。real-time は complete response が再生時間より速いこと。streaming でも first frame でもない。

Base H3 レーン（Diffusers vs vLLM-Omni、50-point dense BF16）と FastH3 duration sweep は別 evidence lane。同じ SHA / prompt / seed / artifact ではないので base-to-FastH3 speedup は出さない、と明記。

Base レーンの Client E2E: Diffusers 82.239 s、vLLM-Omni 56.917 s。complete-response latency 30.8%、1.445x。Peak HBM/rank: 151.699 vs 128.232 GiB。解像度表記 1344x768 / 24 FPS。FastH3 レーンは Dense/Data-Free T2VA only。

告知ツイは別ページ。ローカル Comfy の 4060 Ti 数字とも別世界。

所感

サーブ側の real-time 定義が厳しい（complete MP4）。ローカル 4-step 話と混ぜない。

体験

箱でブログ HTML を取得（HTTP 200）し、script/style を除いて本文を読んだ。vLLM-Omni のサーブは立てていない。B300 も無い。

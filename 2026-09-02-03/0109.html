Agent開発の3方向 — 垂直はSkill/MCP止まり、基盤はpi/Codex/dsh

https://linux.do/t/2842329

LINUX DO develop。@velricer。posts 2。純議論。自分が理解している Agent 開発を3層に分けて、企業はゼロから runtime を書くのか、業務フローに tool/skill を積むだけなのか、と聞いている。

1) 具体シーンのワークフロー（授業で買う系の LangGraph デモ、データの流れに API を挿す）。2) 自分で平台を作り、その上に tool / MCP / skill（電商・金融の流れを包む）。3) ゼロから Agent を設計（runtime、plan、多ツール、多 skill、多 MCP の選択と検索、ツール失敗戦略、A2A、コンテキスト、記憶、権限、安全。1→多、短→長）。基盤設計はすでに pi / Codex / dsh があるので二次創作はできる、企業側に要る能力は何か、という問い。

返信は1件。@mazilian は2番（垂直領域 Agent）に同意。保険・法律の大きな塊はあるが、ストリーム暗号化最適化、組込み、文史研究、特定流派の創作など細分は少なく、skill と MCP はあっても「開いてすぐ使える」水準ではない。

velricer「现在的agent的基础设计的其实已经有了（pi，codex，dsh），可以基于这个来二创开发，那企业做的agent开发到底需要什么样子的能力勒？是还需要从0开始设计agent，还是就是去设计业务的流程，然后来开发tool，skill这种只需要去搭积木就好了？」

mazilian「现在垂直领域的只有几个大的块，比如，保险领域的，法律领域的，之类的，但是具体到细分的垂直，感觉并不多……可能有一些 skill 和 MCP，但是还没有达到一个上手即用的标准。」

所感

ハーネス名を基盤として置いたうえで、企業は積木かゼロからか、という問いが現場向き。垂直の「上手即用ではない」が短いが具体。

体験

スレ JSON を読んだ。pi / Codex / dsh 上での二次創作は未実施。

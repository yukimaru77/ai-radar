誰が何を主張しているか

grey-area: エージェント専用の別ユーザにした方が安全では。petesergeant が返して、別ユーザ同士でも互いのデータに触れる、と釘。

walrus01: OpenCode類を机の下のKVMに隔離。ユーザの ~/Documents・~/.ssh・APIキーは載せない。プロジェクトごとにVMを複製して依存関係を入れる。ノートPCを閉じてもVMは回し続けられる、が利点。

teekert: Zedを開いたらサイドのエージェントがClaudeログイン済みで、ls の出力に private SSH keys が流れた。「ファイル自体は出ていないと思う。cat はしていない」。以後は Claude Code をコンテナに入れ、資格情報/メモリはプロジェクトごと、リポは1つだけマウント。ネットワークはまだ触れる、と自覚。Phemist は ls の結果がClaudeに戻るのでは、と指摘。

nameless912: 記事がAI生成臭、と切りつつ中身は認める。価値は 良いMCP で必要な面だけ出すこと。CloudflareのMCPを好例、Chrome DevTools MCPはブラウザサンドボックス＋JS全アクセス相当で弱い、と対比。自分は Hermes を DigitalOcean VM に置き Tailscale だけ受け、資格情報は専用で revocable。rootを渡すこと自体は、箱に価値がなければ問題ではない。「Cattle, not Pets」の再発見。

tux3: 要するに「信頼できないコードを自分のUIDで走らせると何でもできる」という話で、サプライチェーン攻撃を知らない人向けの記事、と冷やかし気味。

petesergeant: サンドボックス一覧として https://pleasedonotescape.com/、自分の実装 byre（github.com/pjlsergeant/byre）を「CC in a container + TUI + 暗号化資格情報、いつでも素のDocker/Podmanに戻せる」。

apex_sloth: Grok CLIがリポ全体を上げた件のあと、プロジェクトを別ユーザ＋ハーネス周りにサンドボックス。VMは資源と使い勝手で厳しい。

lowcache（著者）: 全てのMCPが ~/.ssh と同じ権限を持っていて、インストール時stdoutはそれを言わない。ベクトルはプロンプトインジェクション、赤絨毯は権限モデル、と自己要約。chollida1 は「専用ユーザがベストプラクティスでは。明示せずに ~/.ssh に届くのか」と返す。

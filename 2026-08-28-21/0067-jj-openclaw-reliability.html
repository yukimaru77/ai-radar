掘金：Agent を長く走らせる——OpenClaw の可靠性アーキテクチャ

https://juejin.cn/post/7678907389488447514

掘金全文（mark_content）を読んだ実測記事。環境は OpenClaw 2026.7.1-2、Docker サンドボックス、ホスト 2核 / 3.8GB。研究 Agent を数時間走らせ、外部中止・コンテキスト溢れ・ツールエラーの3事故を越えて報告書を出し切った、という構成。

核心洞察

コンテキストは作業記憶、ワークスペースは長期記憶。 進捗は必ず落盤。テスト質問：『セッションを空にしても続きからできるか？』。Run / Session Context / Workspace は寿命が別物。

六層モデル（要約）

①モデル／プロバイダ（SDK再試行・資格情報・fallback）②Agent 意思決定（ここだけモデルの自觉）③ツール実行 ④コンテキスト ⑤ランタイム ⑥観測。②以外は設定やコマンドで強制できる——プロンプトに『DBを消すな』と書くより exec をツール一覧から外す、が本筋。

実測で触れられている事故と道具

1回目 Run は externalAbort=true、2回目は Context overflow、/new 後に reports/ と notes/ を読んで継続。exec の前景／timeout／yieldMs 背景＋process poll を対比。Agent の allow はグローバル allow の部分集合でしか広げられない。再試行は Transport / Agent / Recovery の三層で、HTTP 再試行＝業務フロー再実行ではない。冪等でない外部書き込みは『結果不明なら先に状態確認』。

收官タスクの Transcript 統計（記事表）：ツール呼び出し 30、エラー 1（git log 128）、ツール付きモデル輪 25、最終は正常收尾。行動パターンは『開場でワークスペースを読む／出力を head・grep で有界に／失敗同一呼び出しを繰り返さない／報告前に checkpoint（3.4KB）／最後に ls -l で成果物検証』。

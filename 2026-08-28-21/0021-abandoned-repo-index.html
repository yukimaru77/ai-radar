TheGitAI: リポ索引を捨てて grep→read→run に戻した

https://thegit.ai/blog/why-we-abandoned-repository-indexing

HNタイトルは「Repo indexing was doing more harm than good…」（id=49476449）。本文日付 August 23, 2026、9分。TheGitAI（Atlast Technologies）のエンジニアリングノート。

主張の芯

コーディング前に完全なマップを作る、は魅力的だがソフトウェアはワンショット検索ではない、調査だ、と切る。失敗テストが関数を指し、importが設定を指し、実行が最初の仮説を壊す。5分後に必要なファイルは、ユーザの第一文からは予測できない。

Similarity ≠ relevance。『Fix login』で auth routes / session / middleware / 古いmigrationが全部ヒットしても、壊れている一本は一つ。OAuth成功後にログイン画面へ戻るバグの例では、先回り索引は auth/login.ts 群を並べ、本番の sameSite 上書きは出てこない。JIT側は rg callback → createSession() → 失敗テストがcookie設定を指す → rg sameSite。各観察が次の質問を変えるのが要点。

容量は注意ではない

Lost in the Middle、長い入力が完璧なretrievalでも性能を落とす研究、RAGの distracting passages を引用。コードベースは古い実装・生成物・テストダブル・同名関数で「それっぽい邪魔」を量産する。コンテキストは倉庫ではなく作業机。Anthropicの context engineering も同じ方向、と書く。

公開エージェントの並行: Claude Codeは glob/grep のJIT、Codexはリポを直接読み編集しテストを走らせる（内部がindex-freeとは言わない、公開面だけ）。

捨てたきっかけはバグ

自前の意味検索が ゼロヒットを返していた期間があり、性能劣化に気づかなかった。直すより「何を失ったか」を測ったら、想定より少なかった。セッションは検索・読み・実行で足りていた。巨大で静的なコーパス、多リポ横断、低レイテンシ繰り返し、語彙が不明な探索、環境を安全に触れない場合は索引がまだ合う、と逃げ道は残す。結論は狭い: 投機的なリポコンテキストを『多い方が安全』で載せない。

HNの著者コメント（waximabbax）も同じ話を短く繰り返す。類似検索はコードで稀にしか効かず、入力トークンと往復を増やした。

体験

ブログ全文を開いた。TheGitAIのCLIは入れてない。索引あり/なしのA/Bを再現していない。製品の無料枠にもログインしていない。

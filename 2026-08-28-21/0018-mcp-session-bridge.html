t3ratech/mcp-session-bridge: 今ログイン中のブラウザをMCPで運転する

https://github.com/t3ratech/mcp-session-bridge

Show HN（id=49476743、2 points / コメント0）。「MCP server that drives the browser you are signed into」。stdioのJSON-RPC。クラウドのブラウザAPIではできない、自分のChromeプロファイルの実セッションを session_* ツールで触る、が売り。

二重トランスポート

Extension mode: ローカルのowner-onlyリレーソケット ~/.t3rnel/session-bridge/bridge.sock → Chromeがspawnするnative messaging host → T3rnel Browser拡張が実タブで実行。Proツールのゲートは拡張側（$29.99買い切り・3台）。ブリッジ自体にライセンス検査はない。READMEは昔の草稿に $9/mo と $39/mo が書いてあったが未実装・未販売、と自己訂正している。

Standalone mode（無料）: 専用CDPブラウザを永続プロファイルで起動。拡張もライセンスも不要。日常ブラウザには触れない。Playwright MCPと同じモデル、と --help が書く。

T3RNEL_SESSION_MODE=auto が推奨。リレーがあれば拡張、なければstandalone。クライアント列は Claude Code/Desktop、Cursor、VS Code、Windsurf、Antigravity、IntelliJ、Codex、Grok Build、Kimi、Cline、OpenCode、Continue、Kilo、Roo、Aider、OpenClaw、Hermes、OpenFang ほか。

ツール面

session_install / session_health / session_list_tabs / session_navigate / session_snapshot / session_read_page / session_click|fill|type|press / session_evaluate / session_screenshot / session_wait。拡張は 98 tools。Node 20+。npm i -g @t3ratech/mcp-session-bridge のあと mcp-session-bridge --install がネイティブホストを登録。

体験

npx --yes @t3ratech/mcp-session-bridge --help は通った。Usageは stdioサーバ / --install / --uninstall。環境変数表はREADMEと一致。--install はChromeマニフェストを書くので実行していない。standaloneでブラウザを起動してもいない。session_health も呼んでいない。T3rnel拡張のインストールページは別URLなので別ページ。

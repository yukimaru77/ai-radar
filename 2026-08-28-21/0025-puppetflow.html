Puppetflow: ソースアベイルのブラウザ自動化（self-hostはdocsが「coming soon」）

https://github.com/puppetflow/puppetflow

Show HN（id=49476246、2 points）。作者 Jess / jierka、フランス、15年開発、約1年この製品。Puppeteerの上に観測とデバッグを厚くしたプラットフォーム。バックエンドLaravel、フロントは vanilla React + Inertia。AI-firstにはしなかった（高い・遅い・予測不能）。モデル接続は「話せる / ブラウザを渡せる」オプション。

README vs ライセンス

機能: JSワークフロー、手動/スケジュール/連携実行、ライブ視聴と介入、変数・秘密・ブラウザプロファイル、実行履歴、1Password等vault、Docker自己ホスト、n8n community node n8n-nodes-puppetflow。ライセンスは Source Available（個人・非商用）。社内利用は有料サブスク。proprietary/ と .pp. マーカーは有料機能。公開git履歴はCommunity Edition公開時にセキュリティ理由でresetした、コミット数は年齢を表さない、と注記。No AI Slop Policyあり。

Show HN本文の痛み

書くのは簡単、壊れたとき「どのステップ・その時のページ・その前・コンソール」が欲しい。ライブビューのUI同期とanti-botが一番キツい。fingerprint-chromiumを試す予定。Blueprintは github.com/puppetflow/library へのPR。

docsの矛盾

docs.puppetflow.com/self-hosting/installation 冒頭は Self-hosting is coming soon、情報は予定で変わりうると赤字。その下に curl -fsSL https://puppetflow.com/install.sh | bash が続く。要件はLinux、RAM 2GB（Chromiumなら4GB推奨）、Docker未導入ならインストーラが入れる。SQLite単一ホストが既定、高書き込みはPostgreSQL。スタックは app:8000、queue、scheduler、pinokio（Chromium gateway:3000）、stream-server:6080、mailbox SMTP:2525、redis、postgres。

体験

master README、install.sh（syntax bash -n はOK）、docs HTMLを開いた。install.shは Docker 28.5.0 を前提に compose を引き .env に APP_KEY / BROWSER_STREAM_SECRET / PINOKIO_TOKEN を生成する。パイプ実行はしていない。この箱にdockerは無い。localhost:8000 も上げていない。n8n nodeも未インストール。--help 相当の単体CLIはリポに無く、入口はDocker。

almogdepaz/wolfpack: Rust PTYブローカーのセルフホスト制御室

https://github.com/almogdepaz/wolfpack

Show HNのランディングから辿った本体。README見出しは browser terminal manager for AI coding agents。セッションはWebサーバではなく Rust PTY broker が所有するので、ブラウザを閉じても・Webサーバだけ再起動してもセッションは残る。ブローカー再起動やログインサービスの再インストールは切れる、と明記。

インストール面

curlインストーラはセットアップをすぐ起動し、ログインサービスを受けたなら印字URLを開く。拒否したなら wolfpack を自分で起動。検証は wolfpack doctor。代替は bunx wolfpack-bridge@latest か npx --yes wolfpack-bridge@latest。パッケージランナーはPATHに wolfpack を足さない。アンインストールは wolfpack uninstall --yes。

内蔵プロバイダは Claude Code、Codex、Gemini CLI、Cursor、Pi。Shellは常時フォールバック。PATH上のカスタムコマンドも Settings → Agents で足せる。スキル wolfpack-tailnet-control は Agent Skills 対応ハーネス向け。Pi連携は pi install npm:@sgtbeatdown/pi-tasks。

セキュリティとリモート

「browser usersにシェル級の制御を渡す。Tailnetの信頼できる相手に閉じよ。共有TailnetならACLとJWTを検討。セッション間の認可レイヤはない」と警告。リモート操作は --machine <short-name-or-fqdn> で、JWT付きの GET /api/machine ハンドシェイク。無効・非互換・リダイレクト・タイムアウトは fail closed、localhostフォールバックなし。

自動化例: wolfpack session create project-name --harness pi --plan .plans/000-task.md --json、子エージェントは wolfpack agent spawn ... --notify-parent。

体験

npx --yes wolfpack-bridge@1.6.20 --help は通った。Usageは wolfpack [--machine ...] [command]。サブコマンドは setup / service / doctor / list / session / agent spawn / kill / attach / logs / uninstall。--version は 1.6.20。

npx ... doctor も実行した。この箱では Result: 4 failed, 3 passed, 4 warning(s)。落ちたのは ~/.wolfpack/ 不在、config.json 不在、binary 不在、broker binary 不在。警告は Tailscale未インストール、SHELL 未設定、サービス未導入、ブローカーソケットなし。setup は対話ウィザードなので走らせていない。ログインサービスも入れてない。実セッション作成・Tailnet接続・PWAインストールはしていない。

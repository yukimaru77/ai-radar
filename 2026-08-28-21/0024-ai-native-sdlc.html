Anthropic: AI-Native SDLC Playbook（intent.md から本番ループへ）

https://claude.com/blog/the-ai-native-sdlc-playbook

HN（id=49477088、3 points / コメント0）。Claude.com の長文プレイブック。JSON-LDのheadlineは The AI-Native SDLC playbook。Applied AIチームが社内と顧客で回した「6段階をエージェント前提で組み直す」手順書。Claude Code の宣伝だが、成果物チェーン（intent.md → spec.md → plan.md → diff/tests → PR → インシデント記録）が本体。

なぜ今組み直すか

コード生成は1年前には考えられない速度になったが、周りの承認・レビュー・引き継ぎは人間速度のまま。伝統的SDLCは「実装が一番高い」時代の効率最適化で、PRD・見積もり儀式・セキュレビューは何週間〜四半期の実装を揃えるためのものだった。実装が時間に潰れると、(1) ボトルネックは plan / review / deploy に移る (2) 行単位レビューが現実に追いつかない (3) 例外が週次委員会に流れガバナンスコストが上がる。セキュリティチームは人間出力向けの人数なので、エージェントが増やすdiffをさばけず、キューが溜まるか未レビュー出荷になる、と例える。

6段階のシフト

線形ではなくループ。各段階が次が読める成果物をgitに残す。Plan: 委員会要件 → Claudeがソースから痛みを合成し intent.md。Design: アナリスト仕様 → スキル制約の1セッションで spec.md。Build: 手書きテストと後追いdocs → AIがコードとテストを出し、制度知は CLAUDE.md とskills。Test: 段階境界のQAゲート → 実装に編み込んだ継続eval。Deploy: 人間が全行レビュー → エージェント層レビュー＋hooksを承認ゲート、人間は規制・致命コード。Maintain: 人間が本番監視 → エージェントが制御帯を監視し、破れたら新しい intent.md を書き戻す。

Plan / Design の手触り

intent.md に必要なのは形式言語ではない。問題、望む結果、影響ユーザ、制約、未決。例は保険クレームのセルフサービス（コールの約1/3がステータス確認、ポータルに次ステップと予定日、新規PIIなし）。非エンジニアはgitを触らず、claude.ai / Cowork のコネクタでcommit。プロダクトオーナーがmergeまたはcloseする。先行指標は初回会話→commitまでの時間（週単位→時間）、遅行はaccept率と spec.md 後のintent改訂回数。

Designは brand/security/compliance/UX のskillsを載せた1プロンプト。フラグ付きconcernを先に政策オーナーと潰してからエンジニアに渡す。フロントは Claude Design (beta) でモックしてClaude Codeへ。

Build / Test

デフォルトは Claude Code の plan mode。コードを触らず計画を書き、ファイル名・順序・テスト・リスクを plan.md にcommitしてから実装。claims例では StatusPanel.tsx 新規、claims-api/routes/status.py、rate-limit 50 rps をキャッシュで避ける、4状態のテスト、モック一致スクショ。実装が計画から外れたら同じcommitで plan.md を更新。hookで同期強制も提案。auto modeは計画承認後に任せる話が続く。

Testはセッション自身に検証手段を渡す（make test / npm test、UIはブラウザMCPかスクショ）。CLAUDE.md の Commands に健全出力例を書く。バグ修正は失敗テストを先にcommitし、エージェントにテストファイルを触らせないhook。verifier subagentは別物（終わったあと新鮮なコンテキストで最終判定）。

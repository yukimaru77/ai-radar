Command Code prefix cache：100Kのうち新規は最後2K、時刻を挿むと死ぬ

https://x.com/realchendahuang/status/2093879888260505901

同じスレの cache 解説。100K 文脈のうち新規は最後 2K、残り 98K は Cache Read。System Prompt 先頭に時刻を挿むだけで prefix が死ぬ。v0.33.0 changelog は median cost −2.9×、cache hit 95–99%。

原文まわり

CEO @MrAhmadAwais：「cache は 1/10 価格、1–2% の hit 増でも効く」。

Agent 課金はモデル単価より「同じ prefix を何回再計算させるか」。Command Code が Flash 苦力向きと言われる理由の本体がここ。

所感

ハーネス比較で「速い/安い」と語る前に、時刻・ランダムID・毎回変わるヘッダを System 先頭に置いていないか疑う。1–2% の hit 差が請求を動かす。

体験

スキャン原文。公式 GOAT ページでも ~98% cache と Read tool で junk 25B tokens/月を外す、と書いてあった（別ページ）。実測の hit 率は未取得。

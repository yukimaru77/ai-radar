Command CodeはFlashの尻拭い。Piは基座、OMPは兵工廠

https://x.com/realchendahuang/status/2093883062505599424

@realchendahuang が Pi / OMP / DeepSeek Harness / OpenCode / Command Code を同じ軸で切った。GOAT対Goの価格話は既出。新しいのは役割分担。開放モデルの「強さ」はモデル単体では測れない。

原文

「Command Code 的路子不大一样。它特别喜欢替模型擦屁股。Tool Call 参数写错了，Harness 本地修；文件刚读过又要重复读，Harness 帮你去重」

「如果只看长期可塑性，我依然更喜欢 Pi。但如果今天就让我拿 DeepSeek V4 Flash/ GLM-5.3狠狠干活，我现在真会尝尝 Command Code的咸淡。」

位置づけ：Pi＝長期の自分用基座（軽い、介入少ない、魔改しやすい）／OMP＝LSP / Debugger / Browser / AST を積む兵工廠／DeepSeek Harness＝Everything is Plugin／OpenCode＝汎用・多プロバイダの総合型／Command Code＝Flash 苦力の尻拭い（Tool Call Repair / 重複read除去 / Stable Prefix / Session Affinity）。

所感

同じ GLM Flash でもハーネスで速度・コスト・成功率が割れる。Flash を主戦力にするなら修理レイヤと cache を先に見る。Pi を基座にする人は、逆に修理を足しすぎない。

体験

スキャン原文と status URL を照合。Command Code 本体は公式 GOAT ドキュメントを別ページで開いた。CLI 実機で Tool Call Repair は未実行。

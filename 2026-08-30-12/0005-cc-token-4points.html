Claude Code：同じ仕事でもトークンが倍になる4点

https://x.com/oikon48/status/2093897746159935924

@oikon48。/clear vs /compact 自体は既出。新規は運用手順の束ね方。

4点

1. 長いセッションは毎ターン全文再送 → タスク終了で /clear、要約が要るときだけ /compact。

2. 読んだファイルとコマンド出力はセッション終了まで残る → 説明せず @ で指す。出力が多いコマンドはサブエージェントへ。

3. モデルと effort はコストを倍増させ、デフォルトは前回セッションの設定 → 開始前に /model /effort を確認。

4. プロンプトキャッシュは モデル / effort / モード切替で消える → 会話途中で切り替えない。

所感

「同じ仕事なのに倍」の原因が、モデルの賢さではなくセッション衛生。Command Code 側の prefix 死（時刻挿入）と同じ系統の現場知。

体験

スキャン原文。公式 prompt-caching docs は別ページ。CC 実機で切替コストは測っていない。

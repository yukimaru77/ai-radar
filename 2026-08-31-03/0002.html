Skillのdisable-model-invocationはハーネスごとに別物。入口を閉じるだけで保安境界ではない

https://x.com/GetAgentTools/status/2094123933121249635

@GetAgentTools の 7連（18:03–18:07 UTC）。55本の SKILL.md を監査したら 18本が deploy / 送金 / 課金 / 本番 mutate。初回はどれも model invocation を止められていなかった。8本を切ったあとの差分がこのスレの中身。

Claude Code: disable-model-invocation: true は /skill-name を人間に残してモデル経路だけ切る。user-invocable: false はその逆（コマンドが消えて Claude はまだ読める）。8本をモデル不可にしたら skill listing から 1,745文字 落ちた（コンテキスト節約）。

Cursor / VS Code Copilot / Zed は同じ frontmatter。Copilot CLI は未ドキュメント。Gemini CLI は抑制フィールドなし。Codex は policy.allow_implicit_invocation: false in agents/openai.yaml。Claude の frontmatter は効かない。$skill 明示は残る。

OpenCode は未知 frontmatter を無視。制御は opencode.json の permission。ある runtime で制限に見えて別 runtime ではモデル起動のまま、がこの監査の本丸。

「These settings close an intended entry path. They do not remove shell access or create a security boundary.」

Field note 本体は https://getagenttools.com/blog/disable-model-invocation/（別ページ）。スレは監査数字とハーネス差分の速報、ブログは docs 照合と blast-radius 基準。

「同じ SKILL.md を共有フォルダに置けば全ハーネスで止まる」は成り立たない、という現場。フラグは入口を閉じる。シェル3コマンドのデプロイは残る。
